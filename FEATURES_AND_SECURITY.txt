  1. SYSTEM OVERVIEW
================================================================================

  The Internship Performance Management System is a full-stack web application
  designed to manage internship programs. It enables:

    • HR to approve/reject intern registrations and assign them to team leads
    • Team Leads to create coding tasks, assign them, and review submissions
    • Interns to complete tasks in a built-in code editor with live execution
    • All roles to track performance, scores, and progress

  Architecture:
    • Backend  : Laravel 11 (PHP 8.2+) with Sanctum token-based authentication
    • Frontend : React 18 with Vite, React Router v6
    • Database : MySQL (internship_db)
    • Code Exec: Judge0 CE (free open-source, ce.judge0.com)
    • Email    : SMTP (Gmail) for password reset emails

  3. MODULE 1 — AUTHENTICATION & AUTHORIZATION
================================================================================

  FEATURES:
    • User Registration with role selection (intern / team lead)
    • Login with email & password
    • Forgot Password — sends a reset link to registered email via SMTP
    • Reset Password — token-validated password change
    • Logout — invalidates server-side Sanctum token + clears localStorage
    • Auto-redirect — logged-in users are redirected away from auth pages

  PAGES:
    • /auth/login            → Login page
    • /auth/register         → Registration page
    • /auth/forgot-password  → Request password reset email
    • /auth/reset-password   → Set new password using token

  SECURITY FEATURES:
    ✔ Sanctum Token-Based Authentication (stateless API tokens)
    ✔ Password hashing with bcrypt (12 rounds)
    ✔ Account status check — only 'approved' users can log in
    ✔ Pending users get 403 with "account is pending approval" message
    ✔ PublicRoute guard — prevents logged-in users from accessing auth pages
    ✔ ProtectedRoute guard — prevents unauthenticated users from accessing
      dashboard pages; redirects based on role if role mismatch
    ✔ 401 auto-logout — if any API call returns 401, the frontend clears
      tokens and redirects to login page immediately
    ✔ Token stored in localStorage as 'auth_token'
    ✔ User object stored in localStorage as 'user'

  BACKEND CONTROLLERS:
    • AuthController     → register, login, logout, user, myStats
    • PasswordResetController → sendResetLinkEmail, reset

    • Standard Input (stdin) — custom input panel for testing
    • Theme Toggle — switch between dark and light editor themes
    • Font Size Controls — adjustable A-/A+ buttons
    • Word Wrap Toggle
    • Auto-save — drafts saved every 30 seconds automatically
    • Manual Save — Ctrl+S shortcut
    • Run Code — Ctrl+Enter shortcut
    • Submit Solution — sends code for team lead review
    • Activity Logging — keystrokes, runs, saves, and paste attempts tracked
    • Left sidebar shows:
        - Problem title, description, difficulty, status
        - Due date
        - Assigned by (team lead name and avatar)
        - Feedback & score (if reviewed)
        - Keyboard shortcuts reference
        - Security notice with paste attempt counter
    • Bottom panels:
        - Output panel (stdout + stderr separated)

    • Fallback: Judge0 via RapidAPI (if JUDGE0_API_KEY is set in .env)
    • Timeout : 20 seconds per execution
    • Polling  : If result is still processing, polls once after 2 seconds
    • Sandbox  : code runs in isolated containers (Judge0 infrastructure)

  SECURITY FEATURES — COPY-PASTE DETECTION:
    ✔ Clipboard paste BLOCKED — Ctrl+V and right-click paste intercepted
    ✔ Paste attempts LOGGED with:
        - Timestamp of attempt
        - Length of pasted text
        - Preview of first 80 characters
    ✔ Paste attempt counter displayed in sidebar (red warning badge)
    ✔ Each paste attempt triggers an error toast: "Paste blocked! Attempt #N"
    ✔ Drag-and-drop BLOCKED — files and text cannot be dropped into editor
    ✔ Right-click context menu DISABLED inside Monaco editor area
    ✔ Copy events are LOGGED (allowed but tracked for audit)
    ✔ All activity (pastes, runs, saves, keystrokes) saved to task activity_log
    ✔ Activity log viewable by team leads during code review
    ✔ Event listeners use capture phase (true) for maximum interception


================================================================================
  8. MODULE 6 — TASK & ASSIGNMENT ENGINE
================================================================================

  TASK LIFECYCLE:
    1. Team lead CREATEs task → status: 'todo'
    2. Intern views task in workspace and opens in code editor
    3. Intern writes code, runs it, saves drafts
    4. Intern SUBMITs solution → status: 'in_progress'
    5. Team lead REVIEWs submission → adds feedback, score → status: 'done'

  TASK FIELDS:
    • title          — Task name (required)
    • description    — Detailed description (optional)
    • difficulty     — basic / medium / hard
    • assigned_to    — Intern user ID (or "all" for bulk assignment)
    • creator_id     — Team lead who created it
    • due_date       — Deadline
    • status         — todo / in_progress / done
    • submission     — Intern's submitted code
    • feedback       — Team lead's feedback text
    • score          — 0-100 numeric score
    • submitted_at   — When intern submitted
    • reviewed_at    — When team lead reviewed
    • draft_code     — Auto-saved editor content
    • draft_language — Language of the draft
    • draft_saved_at — Last auto-save timestamp
    • activity_log   — JSON array of all editor activity

  ASSIGNMENT FEATURES:
    • Assign to SINGLE intern — select from dropdown
    • Assign to ALL interns — creates a separate task for each intern
    • Re-assignment supported — edit task to change assigned_to
    • HR assigns interns to team leads (team_lead_id on users table)

  SECURITY FEATURES:
    ✔ Only teamlead/admin can create, update, delete, review tasks
    ✔ Only the assigned intern can submit a solution (403 otherwise)
    ✔ Only the task creator can review it (403 otherwise)
    ✔ Interns can only read tasks assigned to them
    ✔ Team leads can only see tasks they created
    ✔ HR/Admin can see all tasks

================================================================================
  10. DATABASE MODELS
================================================================================

  USERS TABLE:
    • id, name, email, password (hashed)
    • role_id (FK → roles), technology_id (FK → technologies)
    • status (pending / approved / rejected)
    • team_lead_id (FK → users, for interns)
    • is_active (boolean), assigned_at (datetime)
    • email_verified_at, remember_token, timestamps

  ROLES TABLE:
    • id, name (intern / teamlead / hr / admin)

  TECHNOLOGIES TABLE:
    • id, name (e.g., PHP, Python, JavaScript, etc.)

  TASKS TABLE:
    • id, title, description, status, difficulty
    • assigned_to (FK → users), creator_id (FK → users)
    • due_date, submission, feedback, score
    • submitted_at, reviewed_at
    • draft_code, draft_language, draft_saved_at
    • activity_log (JSON), timestamps

  APPROVAL_LOGS TABLE:
    • id, user_id, action, performed_by, timestamps

  RELATIONSHIPS:
    • User belongsTo Role
    • User belongsTo Technology
    • User belongsTo User (teamLead via team_lead_id)
    • User hasMany User (interns via team_lead_id)
    • Task belongsTo User (assignee via assigned_to)
    • Task belongsTo User (creator via creator_id)

  11. API ROUTES SUMMARY
================================================================================

  PUBLIC (NO AUTH):
    POST   /api/register          → Register new user
    POST   /api/login             → Login and get token
    POST   /api/forgot-password   → Send password reset email
    POST   /api/reset-password    → Reset password with token

  AUTHENTICATED (ALL ROLES):
    POST   /api/logout            → Logout and revoke token
    GET    /api/user              → Get current user info
    GET    /api/me/stats          → Get current user stats
    POST   /api/code/run          → Execute code via Judge0
    POST   /api/code/autosave     → Auto-save editor draft
    GET    /api/tasks/stats       → Task statistics
    POST   /api/tasks/{id}/submit → Submit task solution (intern)
    GET    /api/tasks             → List tasks (role-filtered)
    GET    /api/tasks/{id}        → Get single task
    GET    /api/my-interns        → Get team lead's interns

  TEAM LEAD / ADMIN ONLY:
    POST   /api/tasks             → Create task
    PUT    /api/tasks/{id}        → Update task
    PATCH  /api/tasks/{id}        → Update task (partial)
    DELETE /api/tasks/{id}        → Delete task
    POST   /api/tasks/{id}/review → Review submitted task

  HR / ADMIN ONLY:
    GET    /api/hr/stats              → HR dashboard stats
    GET    /api/hr/users              → List all users
    GET    /api/hr/users/{id}         → Get single user
    PUT    /api/hr/users/{id}/status  → Approve/reject user
    GET    /api/hr/logs               → Audit logs
    GET    /api/hr/assignments/stats  → Assignment stats
    GET    /api/hr/assignments/interns→ List all interns
    GET    /api/hr/assignments/leads  → List all team leads
    POST   /api/hr/assignments/assign → Assign intern to lead
    DELETE /api/hr/assignments/{id}   → Unassign intern
    GET    /api/hr/assignments/leads/{id}/interns → Lead's interns
    GET    /api/hr/assignments/my-interns → Current user's interns

  LEGACY ADMIN (HR / ADMIN / TEAMLEAD):
    GET    /api/admin/pending-users       → Get pending users
    PUT    /api/admin/users/{id}/status   → Update user status
